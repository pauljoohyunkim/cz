Ownership Rules for Symbols and Types in the CZ Compiler

## Symbol Ownership (cz_symbol_table.h)

### Creation and Destruction
- `cz_symbol_create()`: Creates a CZ_Symbol on the heap. Caller owns the returned pointer and must free it with `cz_symbol_free()` unless ownership is transferred.
- `cz_symbol_free()`: Frees a CZ_Symbol object. Does not free any referenced CZ_Type objects (they are const pointers).
- `cz_environment_create()`: Creates a CZ_Environment. Caller owns it.
- `cz_environment_free()`: Frees a CZ_Environment and all symbols it contains.

### Ownership Transfer
- `cz_environment_push_symbol(env, symbol)`: Transfers ownership of the symbol to the environment. After calling this function:
  - The caller must NOT free the symbol
  - The environment becomes responsible for freeing the symbol when it is destroyed
  - The symbol parameter is const to indicate it will not be modified by the function

### Symbol Internal Pointers
CZ_Symbol contains const pointers to CZ_Type objects:
- For VARIABLE: `data.variable.type` - points to a CZ_Type (not owned by symbol)
- For FUNCTION:
  - `data.function.return_type` - points to a CZ_Type (not owned)
  - `data.function.params` - array of CZ_ParamSymbol (each contains name and type pointers)
- For TYPE_DECL: `data.type_decl.type` - points to a CZ_Type (not owned)

These are const pointers indicating the symbol does not own the referenced types.

## Type Ownership (cz_type.h)

### Creation and Destruction
- `cz_type_create()`: Creates a CZ_Type on the heap. Caller owns the returned pointer.
- `cz_type_free()`: Performs a "shallow free" - frees the CZ_Type object itself but does NOT free any referenced CZ_Type objects. This design allows types to be safely used with the global type table.
- `cz_global_type_table_create()`: Creates a CZ_GlobalTypeTable. Caller owns it.
- `cz_global_type_table_free()`: Frees the global type table and ALL types it owns.

### Ownership Transfer
- `cz_global_type_table_push_type(gtt, name, type)`: Transfers ownership of the type to the global type table. After calling:
  - The caller must NOT free the type
  - The global type table becomes responsible for freeing the type when it is destroyed
  - The type parameter is const to indicate ownership transfer

### Type Internal Pointers (by kind)
CZ_Type contains various pointers depending on its kind, none of which are owned by the type:
- PRIMITIVE: No internal pointers
- STRUCTURE:
  - `structure.name` - const char* (not owned)
  - `structure.layout` - points to CZ_StructLayout (not owned)
- REFERENCE:
  - `reference_to` - points to another CZ_Type (not owned)
- NEWTYPE:
  - `newtype.name` - const char* (not owned)
  - `newtype.underlying` - points to CZ_Type (not owned)
- FUNCTION:
  - `function.return_type` - points to CZ_Type (not owned)
  - `function.param_types` - array of CZ_Type* pointers (not owned)

## Key Ownership Principles

1. **Creator Owns Until Transfer**: The function that creates an object owns it until ownership is explicitly transferred to a container.

2. **Containers Own Their Contents**:
   - CZ_Environment owns all symbols pushed into it
   - CZ_GlobalTypeTable owns all types pushed into it

3. **Shallow Free for Types**: `cz_type_free()` does not recursively free referenced types to prevent double-free when types are managed by the global type table.

4. **Const Pointers Indicate Non-Ownership**: Throughout the API, const pointers are used to indicate that a structure does not own the pointed-to object.

## Potential Issues in Freeing

1. **Double Free Risk**: If a caller frees a symbol/type after transferring ownership to a container (environment or global type table).

2. **Memory Leak Risk**:
   - If environments or global type tables are not properly freed
   - If symbols/types are created but never pushed to a container and not freed

3. **Dangling Pointer Risk**:
   - Using symbols/types after their owning container has been freed
   - The const pointers in symbols/types become invalid when the referenced objects are freed

4. **Circular References**: While the current design doesn't show obvious circular references that would prevent proper cleanup, care must be taken that the global type table's `free` function properly handles all types it owns.

5. **String Ownership**: The API comments indicate that names passed to creation functions are "copied internally," meaning the caller retains ownership of the original strings after creation.

## Recommended Usage Pattern

For Symbols:
```c
CZ_Symbol* sym = cz_symbol_create(CZ_SYMBOL_KIND_VARIABLE, "x");
// Use sym...
cz_environment_push_symbol(env, sym);  // Transfers ownership
// Do NOT free sym here!
```

For Types:
```c
CZ_Type* type = cz_type_create(CZ_PRIMITIVE_INT32, false);
// Use type...
cz_global_type_table_push_type(gtt, "MyInt", type);  // Transfers ownership
// Do NOT free type here!
```

When cleaning up:
- Free environments (which frees their symbols)
- Free global type tables (which frees their types)
- Never free symbols/types that have been transferred to containers
